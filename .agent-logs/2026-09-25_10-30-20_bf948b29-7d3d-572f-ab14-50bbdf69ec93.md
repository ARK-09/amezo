## S3: use Cloudflare R2

AWS S3 is the one piece with no free answer — 5 GB for 12 months, then it bills, egress included. [R2](https://developers.cloudflare.com/r2/) gives 10 GB, 1M writes + 10M reads/month, **zero egress charges**, no expiry, and it's S3-compatible enough that your existing presigned-PUT flow works unchanged. Second choice is Backblaze B2 (10 GB, also S3-compatible). Supabase Storage (1 GB) works but pauses with the project; Cloudinary/ImageKit would mean replacing the upload flow rather than configuring it.

Two things were hardcoded to AWS and are now config:

- **`S3_ENDPOINT`** — switches the client and presigner to a provider endpoint *and* to path-style addressing, which R2 needs and the SDK doesn't infer from an endpoint override. Empty = real AWS.
- **`S3_PUBLIC_BASE_URL`** — the host a browser loads images from is *not* the S3 API host on R2 (it's `pub-<hash>.r2.dev` or your own domain). That URL was being built inline in two places from bucket + region; it's now one `ImageUrlResolver`, and empty still produces the AWS URL.

So it's four env vars and no code change: `S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com`, `AWS_REGION=auto`, the R2 API token as `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`, and `S3_PUBLIC_BASE_URL`. All in `render.yaml` and `docs/deploy.md` now.

Verified against the SDK: presigned PUT comes out as `https://<account>.r2.cloudflarestorage.com/<bucket>/<key>` with `content-type` signed — matching what `uploadProductImage` sends, so the PUT authenticates — and unset it stays on the AWS form. App boots clean both ways. **Not verified:** a real round trip to an R2 bucket (needs credentials). The one dashboard step that will bite if skipped is **bucket CORS** — allow `PUT` from your Vercel origin with `Content-Type` in the allowed headers, or the upload dies at preflight while the API looks perfectly fine.
